# 配置模板

`*.example.json` 都是设计模板；`status: template`、空地图列表和必填项 `null` 表示不可直接运行。M0 命令只读取其专用本机配置并校验引擎和地图身份；尚无通用项目配置加载器或训练入口。

| 文件 | 用途 |
| --- | --- |
| `project.example.json` | 任务范围、观测边界、存储预算和相对路径 |
| `local.example.json` | 已提供的 Windows 安装路径及待确认的解释器路径 |
| `local/machine.json` | 未来填写的本机配置，不提交 Git；当前尚未创建 |
| `experiments/bc.example.json` | 随机初始化行为克隆与数据清单引用 |
| `experiments/rl.example.json` | 新版胜负 RL 基线及引擎固定信息 |
| `experiments/evaluation.example.json` | 冻结模型、评测条件和样本预算 |
| `m0.example.json` | M0 脚本所需安装路径、build、地图路径与哈希 |
| `engine.example.json` | 实测 API 身份字段及游戏二进制哈希 |

M0 实际文件为 `configs/local/m0.json` 和 `configs/local/engine-m0.json`，均不提交；见 [M0 说明](../docs/M0_ACCEPTANCE.md)。以下多层配置合并仍是后续设计，不代表 M0 已实现。

`engines/sc2-cn-97579.json` 是已核对的、可提交的国服发行身份清单，包含官方产品/地区、发行名称、API 返回值和哈希，不包含本机路径。它不是对未来自动更新的授权；新的正式 build 应建立新清单。

## 约定

- 所有相对路径相对于仓库根目录解析，不相对于执行命令时的任意目录或配置文件位置。
- 未来加载器按项目默认值 → 实验配置解析；本机配置仅提供路径和平台，不能覆盖 build、地图哈希、迷雾要求及存储上限。
- CLI 参数如果后来引入，也必须写入解析后的配置快照；禁止隐藏覆盖。
- JSON 不允许注释，字段解释放在本文或接口文档。名称、单位、可空性变更时更新 `schema_version`。
- `latest_stable_at_verification` 只是目标约束，不是启动器可接受的版本值。运行前必须获得具体版本和数据哈希，禁止静默回退到 `latest`。
- RL 地图项未来需包含地图标识、文件 SHA-256 及相关依赖；历史 BC 的每个版本桶通过数据清单固定原引擎和地图。
- `verified_at` 使用带时区的时间戳；`seed` 是候选默认值，不能代替实际出生位置和客户端运行结果记录。
- 模板没有完整的网络和损失系数；后续忠实复现及缩小实验应分别补齐、审阅、固定，不能由框架未记录的默认值决定。

## 100 GB 预算

采用十进制字节：100 GB = 100,000,000,000 bytes。工作规划为 80 GB，20 GB 用作峰值余量；项目新增的外部环境、历史引擎、下载及临时副本也计入预算。

此配置尚不具备自动执行限制的能力。未来下载和解码任务必须先检查实际可用空间与预计峰值；超过上限先请求用户，不自动删除已有数据。

## 复现与本机路径

运行快照应保存实际解析值、代码 commit、依赖锁哈希、数据／动作／特征 schema 和输入文件哈希。提交到 Git 的摘要应去掉本机绝对路径及敏感标识；完整快照放在被忽略的运行目录。

Python／PyTorch／CUDA 候选见[技术方案](../docs/SC2_TVT_RESEARCH_PLAN.md)。`pyproject.toml` 仅声明基础包元数据和构建后端，既不是训练依赖集合，也不是依赖锁。
