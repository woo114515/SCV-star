# M4 BC v5 方案：训练时校准选兵停止

状态：**方案就绪，未训练**。日期：2026-11-13。依据：[选兵失败模式诊断](20261113_M4_bc_selection_diagnosis.md)。

## 依据

1. 标定后五个检查点的选兵 F1 只差 0.009（0.778—0.787），说明**选兵表示已经饱和**，v4 那类“给解码器更多上下文”的改动没有空间。
2. 同一份 v3 权重，自由解码时只选 3.7—3.9 个单位、真实是 5.97 个；把停止 logit 压低 4，F1 从 0.631（C）／0.686（B）升到 0.787／0.841，规模回到 5.8—6.1。
3. 这个 −4 偏置在测试集上同样有效（B 0.674→0.822），但它是一个**在验证集上扫出来的常数**，没有训练依据，且只能补偿“平均意义上的”偏差。

## 唯一改动：规模头（length head）

在 `BCModel` 增加一个辅助头，从 `[state; ability_emb; kind_emb; pooled]` 预测 `log1p(|S|)`（`|S|` 为该步人类选中的单位数，已由 `selected_mask.sum(-1)` 提供，不需要改缓存）。训练损失加一项 `length_weight * Huber(length_pred, log1p(count))`。

解码时两种用法（先实现第二种）：

- **stop_at_count**：按预测规模 k 连续选 k 个单位再停（k 由四舍五入得到，至少 1）。确定性、可复现，直接对齐“选多少个”。
- 或者把预测规模换算成逐行的停止偏置（保留当前的停止头）。

**为什么不是计划采样**：计划采样（用模型自己的前缀训练选兵）更根本地解决暴露偏差，但它同时改变选兵损失的输入分布，和“只修停止”相比是更大的改动。按项目“一次只改一项”的规矩，先用规模头；若规模头不足以把 bias-0 的 F1 拉起来，v6 再做计划采样。

## 配置

与 v3 完全一致，只多一个 `length_head_weight`：

| 项 | v3 | v5 |
| --- | --- | --- |
| 能力头 | MLP 512（384 入） | 同 |
| 选择解码器 | 512 入、GRU 128 | 同（不开 `selection_uses_pooled`） |
| 规模头 | 无 | **新增，权重 0.25** |
| 批／学习率 | 2／3e-4 余弦 → 1e-5、107,000 步 | 同 |
| 预算／种子 | 7,200 训练秒／20261108 | 同 |
| 补齐步 | 已按 `step_mask` 排除 | 同 |

## 判据（事前固定）

参照 v3 在**新口径**下的数字（验证：A 0.4422／C 贪心 0.6309／C −4 0.787；真实规模 5.97）：

1. **主判据**：验证集 `C` 模式、**偏置 0** 的选兵 F1 ≥ 0.75（即把 −4 偏置约 0.16 的收益大部分内建），且预测规模落在 5.4—6.5。
2. **次判据**：验证 A（训练度量）不下降（≥0.4422），能力 top-1 ≥0.599。
3. **测试**：只评一次，`C` 偏置 0 的 F1 需高于 v3 的 0.772（v3 用 −4 偏置）才主张改善；否则按“未达成”记录。
4. 不换种子重跑，不按测试分数挑检查点。

## 成本

- 代码：模型头 + 损失项 + 解码路径 + 单测，约 1 小时。
- 训练：7,200 训练秒，墙钟约 2 小时 20 分（不要再在训练期间跑 CPU 重任务，v4 因此少跑 13% 步数）。
- 评估：验证诊断约 5 分钟；单次测试评估约 6 分钟。

## 风险

- 规模头的误差会直接变成选兵数量的误差：若它对大集合低估，仍会少选。解码时用四舍五入并对 ≥1 截断，可避免空选。
- 辅助损失权重 0.25 可能偏大或偏小；这是唯一新增的超参，若首轮失败，下一轮只调它。
- 规模头只能修“选几个”，修不了“选谁”；后者已确认饱和（0.78—0.79）。
