# M4 BC v1：86383 首次行为克隆训练

状态：**实现、APM 标注、加权缓存与测试缓存完成；过拟合门未达标（能力 top-1 约 0.55 vs 0.90），2 小时训练已启动，最终测试待续**。本记录先固定实验设计、数据契约和判据，训练与测试结果在完成后补入。日期：2026-11-08；负责人：Ubuntu/DSH；种子 `20261108`。

## 假设与单一变量

- 要回答的问题：在冻结的 86383 人类 TvT 数据上，随机初始化的实体＋标量编码器、两层 LSTM 与带条件掩码的多头动作输出，能否完成可复现的 BC 训练、验证学习信号并精确恢复断点？
- 对照组／实验组：本首轮没有超参数对照组；基线为“训练集最频繁能力”的验证集 top-1，以及首轮验证损失。
- 唯一主变量：无（首轮是链路与学习曲线基线）。后续容量、序列长度、特征扩展各开独立实验。
- 主指标：验证集各头损失、能力 top-1／top-5、单位选择 micro-F1／精确匹配、目标类型与目标单位准确率、目标点 MAE、排队准确率、延迟 MAE，以及训练吞吐与显存。
- 判据：小样本过拟合通过；断点恢复下一步逐位一致；2 小时运行完成且最终验证损失低于首次验证；验证能力 top-1 高于训练集最频繁能力基线；测试集只在最后评估一次。

### 输入白名单与缩减

v1 使用实体 27 个 `UNIT_FIELDS` 值、`stale`、实体 mask、8 个标量与 `loop`。实体编码器把 `unit_type`／`alliance`／`display_type`／`stale` 作为嵌入，其余 19 个连续字段按训练集均值／方差归一化，5 个布尔字段保持原值。目标点用地图尺寸归一化，仅用于损失与指标，不把静态地图作为输入。

明确延后：订单、附件关系、载员、buff、升级、战争迷雾／菌毯图像、静态地形／通行／建造网格、雷达 blips、跨块 LSTM 状态、Z 条件、AMP 和更大模型。以上不声称已复现 DI-star 的完整特征。

### 动作头

| 头 | 输出 | 条件 | 损失／掩码 |
| --- | --- | --- | --- |
| ability | 4,119 类 | LSTM 状态 | 全部行 CE |
| kind | command／autocast，2 类 | LSTM 状态 | 全部行 CE；原因见下 |
| selection | 实体指针＋停止符，自回归 | 状态＋ability＋kind | 逐步 CE；无截断；顺序保留 |
| target_kind | none／point／unit，3 类 | 状态＋ability＋kind＋选中摘要 | 全部行 CE |
| target_unit | 实体指针 | 上述＋target_kind | 仅 unit 目标 CE |
| target_point | 2 维，sigmoid | 上述＋target_kind | 仅 point 目标，按地图尺寸 MSE |
| queue | 2 类 | 上述＋target_kind | 仅 command 且队列标签已知 |
| delay | 1 维，`log1p` | 上述＋target_kind | 仅 `delay_mask`，MSE |

初始权重：ability 1.0、kind 0.5、selection 1.0、target_kind 0.25、target_unit 0.5、target_point 0.5、queue 0.25、delay 0.25；未做超参数搜索。

### 计划外但由数据触发的修正

真实 86383 数据中 ability 316（Effect Repair SCV）同时以 `unit_command` 和 `toggle_autocast` 出现；原计划的“由 ability 推导 kind、冲突即失败”分支被触发。为避免丢弃该动作或伪造 kind，v1 增加独立的 **2 类 kind 头**，缓存保存每行 `kind` 标签，词表诊断字段 `ability_kinds` 保留每个能力的全部观测 kind。动作类型总数由 7 个变为 8 个；这不改变动作空间，只修正了原始 action 的类型语义。

## APM 数据质量与加权采样

按用户明确要求，APM 作为数据质量／段位代理。为避免与 Windows 未提交的 `bc_quality.py` 重复，本分支独立实现 `src/scv_star/data/bc_apm.py`：只读冻结 qualification audit 与 1,000 份 API evidence，按每玩家视角的 `player_apm` 标注，不修改任何证据。

- 阈值：>250 high；150—250（含）medium；<150 low。
- 全量：1,000 文件／2,000 视角／2,467,676 行；high 1,124 视角／1,759,808 行，medium 197／213,642，low 679／494,226。
- 86383：训练 152 high／34 medium／56 low（248,546／26,840／50,975 行）；验证 20／9／1（30,085／6,093／516）；测试 24／3／1（44,644／3,820／840）。
- 采样权重：high 3.0／medium 2.0／low 1.0；每个 epoch 以带替换的加权抽取保持序列数不变，验证／测试保持自然分布并报告分质量指标。
- 质量清单 `data/manifests/quality/apm-2026-11-09/quality.json`（SHA-256 `f15141e41b2c9ca08bd145e8b757b27d570d9e6c163ef45492556578b789c436`）；指针 `data/manifests/quality-current.json`；缓存记录 `apm_manifest_sha256`。这些是本地派生元数据，不提交。
- 语义：APM 是活动量代理，不是直接 MMR；按用户决定用于加权采样，报告中保留此限制。

## 缓存与训练实现

- `src/scv_star/data/bc_catalog.py`：按 build 对已验收子清单的 `ability_ids` 取交集，并断言所有观测能力在交集内。
- `src/scv_star/data/bc_cache.py`：使用现有 `iter_collection_rows`／`iter_sequences`／`collate`，把 32 步序列写成张量分片；只从训练集计算 19 个连续实体字段和 9 个标量的均值／方差；测试缓存只复用训练缓存的统计、词表与 ability-kind 诊断。
- `src/scv_star/models/bc.py`：实体／标量编码、两层 LSTM、8 个动作头、掩码损失和采样接口。
- `src/scv_star/training/checkpoint.py`：原子保存、`weights_only=True` 读取、逐字段状态比较。
- `src/scv_star/training/bc.py`：可恢复训练器；采样器使用 `seed + epoch` 的确定性排列并保存 epoch／index；检查点含模型、AdamW、RNG、采样器、配置／缓存／集合／词表哈希和环境。
- `src/scv_star/training/metrics.py`：能力 top-k、选择 F1／精确匹配、目标与延迟指标；测试集不参与调参。

## 预算与执行

- 缓存构建：读取 86383 训练／验证冻结分片，写入 `data/interim/bc-86383-v1/`；实际序列数、行数、字节数与耗时见结果。
- 小样本过拟合：1—2 场录像、500 次更新，检查每个活跃头损失下降与能力 top-1 ≥ 0.9；随后做“保存→恢复→下一步”逐位比较。
- 2 小时训练：训练集全量，batch 2 序列 × 32 步，FP32，AdamW、weight decay 1e-4、梯度裁剪 1.0，每 900 秒保存 `last.pt`，按验证总损失保存 `best.pt`。与计划的偏差：学习率由 2e-4 降为 1e-4（过拟合探测出现 NaN 后按预定方案降 lr）；验证间隔由每 1,000 次更新改为每 5,000 次更新（本机约 12.5 次更新／秒，而训练预算只统计训练步耗时、不含验证，1,000 的间隔会让约 90 次验证额外占用近一小时墙钟，5,000 仍保证约 18 个验证点）。两项偏差都在结果中保留原计划值以便对照。
- 最终测试：训练结束后用 `best.pt` 对测试集评估一次；不据此调整超参数或检查点。
- 数据处理、训练、验证和测试时间分别记录；显存、更新数、样本数、吞吐与检查点 SHA 写入运行报告。

## 评测结果

- 缓存：**完成**。训练 10,546 序列／326,361 行／22 分片；验证 1,197／36,694／3；11,740,323,008 字节；构建 1,908.9 秒；`cache.json` SHA-256 `c3a87f0350a7c7a904e379bb5b6d4e668420cf251f043d4811726eca5f2a1c33`；`apm_manifest_sha256` `f15141e…c436`。训练序列按质量 high 8,011／medium 887／low 1,648；训练视角 152／34／56，验证 20／9／1。
- 测试缓存：**完成**。1,584 序列／49,304 行；复用训练缓存统计、词表与 APM 标签。
- 单元测试与 Ruff：**146 项**（145 通过／1 项 Windows 专用跳过）；Ruff 72 个已跟踪 Python 文件格式与静态检查通过；覆盖 APM 标注、缓存质量摘要、加权采样与加权断点恢复。
- 小样本过拟合：**门未达标**。2 场高 APM 录像，500 次更新训练子集能力 top-1 0.532；2,000 次仍为 0.552（验证 0.511），选择 F1 0.290，目标类型 0.910；未达到计划的能力 top-1 ≥ 0.9。修复了全掩码实体步导致的 Transformer NaN（`nan_to_num`、非有限损失守卫、lr 1e-4）后，验证损失已有限。该不足作为首轮限制记录，直接进入 2 小时基线训练。
- 2 小时训练：**运行中**，输出 `artifacts/runs/bc-86383-v1-apm-20261109T161217Z`；首次尝试 `artifacts/runs/bc-86383-v1-apm-20261109T160631Z` 在第 501 次更新（约 41 秒）被外部终止，未写检查点、无异常栈，因此重新启动且不续训；完成更新数、吞吐、显存、验证曲线和 `best.pt` SHA 待补。

## 结论与下一步

- 是否支持原假设：待 2 小时训练与最终测试后填写。
- 限制：单 build、单种子、精简特征、每 32 步重置 LSTM、无在线合法性／完整对局；小样本过拟合未达 0.9（约 0.55），首轮基线可能欠拟合；APM 是活动量代理，按用户决定作为质量／段位代理用于采样，不能把它当作直接 MMR 或胜负证据；不能据此宣称段位或完整 M4 完成。
- 后续：对比 APM 加权与无加权对照；根据验证曲线决定多 build、多 seed 或特征扩展；M3 在线动作合法性与最新版 API 复验仍在 Windows 侧。
