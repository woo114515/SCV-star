# 小样本观测—动作对齐

这是数据收集之后的下一步，完成M2尚缺的时间对齐验证，并为M3的TvT动作适配建立证据。当前阶段不运行BC/RL，不把粗步长完整回放通过视为训练数据就绪。

## 首轮范围

使用已有严格回放通过、轻筛合格的97579国服录像，固定现有引擎哈希、DataVersion及地图；本轮不重新认定该build仍是交付时的最新正式版。先取一场的前2,240 loops，分别观察玩家1与2；逐loop采样，并用步长8重新回放相同片段作动作流对照。仅验证短片段，不替代整场或全835个候选的验收。

当前项目约99.86 GB。单次运行预留64 MB项目空间，诊断目录达到32 MB时停止；运行总预算10分钟，C盘至少保留20 GB。游戏启动日志和压缩观测计入目录用量，周期检查存在短暂超量的可能，预留空间用于吸收该差异。不新增依赖或引擎，不自动下载重放资源。

## 要验证的契约

1. 固定完整引擎身份和录像哈希；逐视角开启RAW接口、保留迷雾、关闭score和额外隐身显示，检查玩家ID与开局可见性。
2. 记录API动作执行loop与收到动作的观测loop，完整保留同loop多条命令，不自动去重或按胜者筛选。
3. 同时保存动作前1与2 loops的候选观测；找不到对应帧明确计数，不取未来帧补齐。检查选中tag是否存在且属于己方，记录单位目标是否存在。该检查不是完整动作合法性掩码。
4. 诊断输入仅保存 `game_loop`、`player_common` 和 `raw_data`，不将返回动作、聊天、终局结果拼入策略输入；样本以压缩JSONL保存原始观测protobuf。特征白名单和敌方历史快照语义还需后续审计。
5. 比较相同玩家、相同执行时间窗口的步长1与8的RAW命令序列；保留差异，不因命令数相同就判定一致。不把API动作流一致误称为已经覆盖原录像的所有人类输入事件。

## 依据与不能直接照搬的假设

[暴雪协议定义](https://github.com/Blizzard/s2client-proto/blob/master/s2clientprotocol/sc2api.proto)说明观测返回该玩家自上次观测以来的动作，并为动作标注执行loop；[协议文档](https://github.com/Blizzard/s2client-proto/blob/master/docs/protocol.md#inaccuracies-of-actions)同时指出录像到API动作转换可能有误差。

[DI-star解码器](https://github.com/opendilab/DI-star/blob/12b1c69350ad41e17895c602a66a52d98dd58452/distar/agent/default/replay_decoder.py)采用先收集动作、再按动作时刻获取观测的双遍结构，第二遍从首动作loop减2附近开始。本项目先实测loop语义，不直接照搬旧版本偏移、动作过滤或补tag逻辑。仅证明“观测时间戳小于动作时间戳”，还不足以证明引擎内部执行顺序和状态无泄漏。

## 入口与后续门槛

```powershell
.venv\Scripts\python.exe -m scv_star.runtime.alignment_probe --replay <已有合格录像> --engine configs/engines/sc2-cn-97579.json --local configs/local/m0.json --output artifacts/runs/<新的运行ID> --loops 2240
```

输出为私有诊断证据，不上传逐条观测、玩家信息或来源受限录像。`report.json`记录计时、身份、源码哈希、原件完整性和进程退出；失败也保留报告。`diagnostic_completed`仅表示诊断执行完毕，必须单独查看步长比较与未对齐计数，`training_ready`固定为false。

客户端默认后台启动、隐藏窗口，无需人工操作；这不是无图形初始化的Windows服务模式。首轮仅提取RAW `unit_command`，其他API动作计数但不作为本轮配对对象；自动施法切换等动作类别必须在后续完整动作schema中补齐，不能把本轮子集当作完整TvT动作空间。

后续顺序：定位时间偏移及未解析tag → 用可观测的资源/订单变化核查动作前后边界 → 少量97563国际录像作跨版本对照 → 扩到约10场双视角完整提取 → 覆盖起降、附件、生产队列、变形与技能 → 审核动作逆转换、信息边界、质量分层和划分规则后生成首批训练分片。尚未授权恢复全量完整回放；比赛级去重仍按用户要求跳过，同一文件的两个视角必须属于同一集合，跨副本泄漏风险保持显式记录。

## 2026-10-07首轮结果

国服97579一场Lockdown LE录像的前2,240 loops完成双方视角、步长1与8四遍诊断，额外推进8 loops用于接收边界动作。全流程55.687秒，产物622,143字节。两名玩家分别43和39条RAW单位命令；相同玩家的两种步长命令序列完全一致，逐loop时均在执行时间戳之后1 loop返回。

82条命令均取得提前1及2 loops的候选观测，164个配对离线反序列化校验通过，选中tag均存在且属于己方。本片段未观察到同loop多命令，因此还不能验收该情况。提前1与2 loops哪个符合最终训练输入的状态边界仍待资源/订单变化实验，不能仅凭时间戳决定。原始录像哈希不变，客户端正常退出。

国际97563对照未完成：提权执行上下文无法读取 `tvt-curated/` 原件；沙箱上下文可以读取和校验原件，但SC2启动退出码为536936448。未据此认定引擎或录像损坏，也未修改目录ACL；必须先解决执行上下文对资源的访问一致性。

首轮国服报告的空间扫描会跳过不可读目录，其99.48 GB记录不完整。现已改为遇到扫描错误立即停止，并增加回归测试；在可读上下文完整测得99,860,275,589字节（约99.86 GB），低于100 GB。不得将旧的不完整数值当作释放空间的证据。5项单元测试及Ruff通过。

私有证据位于 `artifacts/runs/alignment-pilot-2026-10-07-cn-001/` 和 `alignment-pilot-2026-10-07-international-001/`，后一项保留启动失败报告。脱敏汇总见[首轮诊断JSON](experiments/ALIGNMENT_PILOT_2026-10-07.json)。下一步首先处理访问一致性并验证动作前状态边界；本轮不新增训练就绪文件。
