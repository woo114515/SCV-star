当前集合为1,000文件的人类TvT数据；原始ability ID、DataVersion、API游戏数据及各版本技能目录分别保留。未实现跨版本语义映射前，读取须按版本形成批次，不能直接合并ability ID，也不将旧观测中的价格或生产时间替换后冒充新版轨迹。

首批种子为 `20261008`，增量候选种子为 `20261019`；增量继承已知初始化指纹的旧split，新组按80／10／10概率固定划分，上表为实际数量。不能根据训练结果挑选测试集，同一录像双方视角归入同一集合。按用户要求未做比赛级去重；已知初始化指纹跨集合数为0，但不能保证识别所有跨来源副本，泄漏风险仍保留。

每个视角须满足：

- 两遍回放到实际终局，双方胜负与录像信息一致；记录额外录制尾部。
- 同遍回放的合法观测与动作配对，至少 128 条样本，策略动作配对率不低于 98%。
- 接受动作经编码及逆转换后与原 API protobuf 完全一致；失败原因计数并隔离。
- 分片哈希、原始录像不变、SC2 退出及存储检查通过。
- 全部分片逐条验收，三个集合可送入 NVIDIA GPU 完成有限值前后向检查；优化器更新次数为 0。

这是已发布集合的数据门槛，不代表其余原始库存通过，也不代表已训练出策略或完成新版部署。

## 时间语义与两遍回放

[暴雪协议](https://github.com/Blizzard/s2client-proto/blob/master/s2clientprotocol/sc2api.proto)返回自上次观察以来的动作及执行 loop；[协议说明](https://github.com/Blizzard/s2client-proto/blob/master/docs/protocol.md#inaccuracies-of-actions)指出录像转 API 动作可能有误差。[DI-star 解码器](https://github.com/opendilab/DI-star/blob/12b1c69350ad41e17895c602a66a52d98dd58452/distar/agent/default/replay_decoder.py)采用先收集动作、再取得对应观测的结构，本项目保留这一思路并实测边界。

97563 和 86383 的受控 SCV 实验中，loop 64 提交生产命令，回放动作时间戳为 64；loop 64 矿物仍为 50、订单为空，loop 65 变为 0 并出现订单。当前采用 `observation_loop = max(action_loop - 2, 0)`，保留两 loop 提前量。这是实测支持的保守契约，未穷尽所有技能时序。

完整录像中，改变观察步长后，API 转换出的目标 tag、甚至命令数可能改变。因此，第一遍只提供候选观察时间；**标签与观测都从第二遍取得**。没有准确提前观测的动作显式隔离，不拼接第一遍标签、不猜测 tag、不取未来状态。两遍动作流是否相等仅作诊断。

## 数据契约与信息边界

行schema为 `tvt-bc-v2`，正式模块位于 `src/scv_star/data/`：`bc_schema.py`、`bc_extract.py`、`bc_accept.py`、`bc_dataset.py`及 `bc_collection.py`。

- RAW `unit_command` 和 `toggle_autocast` 均保留；镜头动作计数但不作为 RAW 策略输出。标签保留原 ability ID、顺序化选中索引、队列标记及单位／坐标目标。同 loop 多命令不去重。
- 双方分别使用自己的合法观测，保留战争迷雾，不开额外隐形／埋地显示。策略输入不含胜负、分数、聊天和返回动作。
- 保存己方资源、实体、生产订单、附件关联、升级、载员、迷雾与菌毯。移除非己方订单、载员和附件信息；历史快照动态战斗数值置零。
- 感应塔雷达点可能没有 tag，多个点均为默认 tag 0。它们单独保存为位置型 `blips`，不虚构单位身份、不进入可寻址实体表。重复非零 tag 仍拒绝。
- 共享地图输入仅含尺寸、地形高度、通行／建造网格及可玩区域；排除可能随玩家视角变化的 `start_locations`。己方出生位置来自己方单位。
- 相邻有效动作保留延迟；隔离动作导致延迟掩码关闭并断开序列。有效零延迟与缺失标签区分。

结构检查及逆转换通过，不等于完整游戏规则合法性掩码。起降、附件互换、技能条件、建造位置等在线合法性与闭环执行仍属于 M3。这里保留完整 RAW 能力及参数，不用脚本宏观动作替代 TvT 目标。

当前使用简化特征白名单，并非逐项复现 DI-star：尚未编码 RAW effects 层、完整护甲／武器属性等。保留这些限制以便解释首轮 BC 表现；扩展特征需要升级schema并重新解码，不能从现有分片虚构缺失信息。API返回的action errors单独统计，目前不把无法明确对应时间的错误强行匹配到某条标签；BC标签表达玩家命令尝试，不保证每次尝试成功执行。

## 文件与运行入口

原始收集快照不改写。当前计划、逐场执行收据、资格审计、GPU检查和清理后终验在私有目录 `artifacts/runs/m2-expand-1000-2026-10-19/`。当前集合引用原100场目录 `data/processed/m2-bc-2026-10-08/86383-v3/` 和本轮900个完整子manifest，早期失败实验不能用于训练。48个扩容临时源码已核验归档至 `artifacts/archives/2026-10-21-m2-expansion-scripts/scripts.zip`，附 `manifest.json`；一次性脚本不再作为活跃命令。

每场保存双方压缩JSONL、隔离记录、地图静态数据、API单位／技能数据和报告。`manifest.json` 只由完整分片验收生成。恢复或新增提取前核对[交接](HANDOFF.md)和目标目录；不得向已冻结集合补写文件或覆盖现有报告。

```powershell
# 单场完整提取；output 必须是新的 data/processed 子目录
.venv\Scripts\python.exe -m scv_star.data.bc_extract --replay <录像路径> --engine configs/engines/sc2-international-86383.json --local configs/local/m2-86383.json --split train --output data/processed/<新目录>
# 复核当前集合读取及有限梯度；用新的输出路径，不进行优化器更新
.venv\Scripts\python.exe -m scv_star.runtime.bc_reader_check --collection data/processed/m2-expand-2026-10-19/collection.json --output artifacts/runs/<新检查目录>/gpu-check.json
```

集合读取接口为 `iter_collection_rows(collection_path, split, builds={86383})`；单个manifest仍可用 `iter_rows(manifest_path, split)`、`iter_sequences(..., length=64)`及 `collate(rows, manifest["ability_ids"])`。不截断实体，保留选中索引顺序和条件掩码。核心张量可送入PyTorch；订单、升级、载员、地图等结构字段留给具体网络编码器。GPU检查的小型能力头不是正式策略网络；归一化参数和采样权重只能从训练集拟合。

## 环境、预算与限制

Windows客户端隐藏窗口启动，无需人工点击，仍会初始化图形。本轮每场使用独立Python进程，父进程核对任务、PID、结果收据及完整manifest；基础设施失败与质量排除分开记录，有界重试不降低验收门槛。原共享进程池曾中断，根因未证实，改用独立进程后复用完整产物并重排未完成项；最终批处理已正常结束，SC2全部退出。

2026-10-19八路提取期间可用RAM最低实测5.42 GB，19:40将上限降为7路。调度按可用RAM及Windows提交余量派发：分别保留6 GB／4 GB，每个新任务预留1.6 GB／2.5 GB；这些是派发估算，并非峰值保证。空闲磁盘低于25 GB暂停派发，低于20 GB或逼近本轮150 GB上限保存进度并停止；`drain: true` 用于停止派发并等待在途任务完成。

本轮清理前逐项复核，删除127个无效／中断XZ、2个冗余EXE和2个旧配置，共131项、261,687,994字节，并退役两个工作树。保留全部已接受数据、原始录像、有效引擎、地图及审计证据。最终项目逻辑占用约102.40 GB，处于本轮150 GB授权内；准确存储口径及字节数见[交接](HANDOFF.md)，不宣称已恢复到常规100 GB。已有客户端与项目外暴雪共享缓存另计。

完成且关闭的分片由 `bc_repack.py` 无损重新压缩，逐字节验证解压后 SHA-256 不变，保留原／新压缩哈希及恢复记录。先验证gzip压缩，再使用标准库XZ（preset 3）降低重复观测占用；`bc_storage.py`统一读取两种格式，不新增依赖。发布训练 manifest 后禁止重压缩或改写。早期失败、被替代的分片清理前记录哈希，保留报告与隔离证据。

旧录像目录的跨执行身份访问差异已解决：保存原ACL，只给当前游戏运行用户补充读取权限。历史97579启动失败不代表当前旧版环境仍不可用：2026-10-19恢复的96999／97579需将EXE放在CN缓存根自己的 `Versions/Base<build>/` 中，再匹配CN安装根；仅指定跨根 `-dataDir` 曾立即退出，调整后API身份及受控SCV时序通过。国服2026-10-12重装清单为5.0.17.98370，当前安装API仍待复验；最新版RL／真人部署前须重新固定正式版本并验收。

本集合支持后续流程复现和受控质量比较，不能承诺对战水平。黄金与赛事录像保留来源标签，后续按相同预算比较采样收益。Spawning Tool须署名、回传最终成果且不得再分发；原始和派生数据、玩家详情及逐场清单只留本机，GitHub只保存代码、文档和脱敏汇总。
