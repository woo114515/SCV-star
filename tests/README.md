# 测试规划

当前使用标准库 `unittest`，`unit/test_m0_guards.py` 验证版本漂移、缺失身份字段、地图变更、协议错误及观测配置。运行 `.\.venv\Scripts\python.exe -m unittest discover -s tests/unit -v`。真实客户端验收通过 [M0 命令](../docs/M0_ACCEPTANCE.md) 单独运行，不在单元测试中隐式启动游戏。

当前共17项回归检查：14项 M0 检查也覆盖真人房主接口分离及测试工人损失后的选择；`test_m1_checkpoint.py` 的3项负例检查拒绝优化器计数变化、缺少随机数状态或张量精度变化。缺少 PyTorch 时明确跳过这3项，不能计为通过。真实 GPU 检查通过[M1入口](../docs/M1_ACCEPTANCE.md)单独运行。代码提交前执行 Ruff 格式与静态检查，命令见[开发说明](../docs/DEVELOPMENT.md)。

| 目录 | 未来覆盖范围 | 依赖边界 |
| --- | --- | --- |
| `unit/` | ID 语义、序列对齐、终局与截断、返回值计算、掩码、指标 | 尽量不启动 SC2；真实数值逻辑出现时再选定框架 |
| `integration/` | 固定引擎连接、TvT 能力、实际录像解码、GPU 前后向和恢复 | 明确标记游戏、地图、数据、GPU 条件；缺依赖报告未运行 |
| `fixtures/` | 人工构造的小型元数据或协议样例 | 可提交文本样例；不放私有录像、游戏资源、凭据或模型 |

命名采用 `test_<behavior>.py`。尚未设置覆盖率阈值、pytest 或 CI；单元测试通过不代表游戏、GPU 或训练通过。

首批有意义的测试：未知版本拒绝回退；同一比赛双方与所有切片不跨集合；动作前观测对齐；修改 critic 专用信息不改变 actor logits；起降／附件／队列／变形执行；终局与时间截断的 bootstrap 区别。

测试用的脚本动作只用于检查接口，不加入执行策略。集成测试产生的录像与日志放到 `artifacts/`，单独计入存储预算。
